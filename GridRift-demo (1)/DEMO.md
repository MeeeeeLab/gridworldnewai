# GRID//RIFT：双人第一人称竞速对战 Demo

一个本机 TCP 服务端、两个独立 Java 客户端、两个 800×640 窗口。每局重新生成 25×25 随机迷宫，随机选择双方出生位置与绿色终点。地图包含环路、分岔、死胡同，以及终点前的三个必经共享关口。

## 启动

运行需要 **Java 21** 和可用的桌面 / OpenGL 3.3 环境。依赖已包含在 lib 目录，不需下载 Gradle 依赖。恢复的源码在仓库根目录 recovered-src，重新构建需要 Java 21 JDK。

- Windows：在 `GridRift-demo (1)` 目录双击 `run-demo.bat`。
- macOS / Linux：进入 `GridRift-demo (1)`，运行 `bash run-demo.sh`。
- 从仓库根目录执行 `bash build-demo.sh` 可编译恢复源码、运行检查，并覆盖原 JAR 和试玩 ZIP；普通试玩无需重新编译。
- 不需要账号、令牌、额外服务器或手动填写端口。端口自动分配，**只监听 127.0.0.1**。
- 退出任一窗口 / 按 Esc 结束整场；重新运行脚本开始新的一局。窗口窄屏重叠时可自行拖动。

如果拿到的是预编译 ZIP，解压后运行包里的 `run-demo.bat` 或 `bash run-demo.sh`，只需 Java 21 运行时，不需要 Gradle。默认关闭音频，因此无声卡也能运行。

## 两种完全不同的操作和攻击

| | 玩家 1：SCOUT 侦察兵（青色） | 玩家 2：SIEGE 重装车（橙色） |
|---|---|---|
| 移动方式 | W/S 前进后退，A/D 原地左右转向 | ↑/↓ 前进倒车；←/→ 原地转向，不能横移 |
| 移动速度 | 每 0.25 秒一格 | 每 0.25 秒一格 |
| 攻击 | 空格：周围 EMP 脉冲，无需瞄准 | Enter：沿炮口方向发射直线轨道炮，必须对准 |
| 射程 | 半径 3 格 | 前方 8 格 |
| 命中效果 | 失速 2 秒，小地图干扰 5 秒，不击退 | 停车 2.5 秒，向射击方向最多击退 2 格；有墙时不穿墙 |
| 冷却 | 3 秒 | 3.5 秒 |
| 自动导航 | N，一局一次，最多 1 秒 | M，一局一次，最多 1 秒 |

两种攻击都会被墙挡住。失速结束后另有 1 秒保护，避免被连续控制。攻击用于争夺路线和拖延对手，没有生命值 / 死亡 / 复活机制。

**同一台电脑共用键盘**：点击任一游戏窗口后，两套按键都生效，可同时控制双方；没有焦点的窗口仍持续运行和同步。切换窗口会释放按键，防止一直移动。不要将没有焦点的窗口最小化。部分键盘同时按很多键会有硬件键位冲突。

## 视野、地图与导航规则

- 摄像机位于角色眼睛高度，跟随格子移动和转向平滑过渡；没有俯视全地图模式。
- 小地图初始几乎全黑，只揭示附近约 3 格且未被墙挡住的区域；探索记录各自保存。
- 已探索区域长期保留；对手标记仅在当前近距离且无遮挡时出现，不会追踪远处对手。
- 未知地形、隐藏对手坐标、导航路径均不发送给客户端。
- 被 EMP 命中时小地图暂时离线，恢复后保留原探索记录。
- 自动导航启动后**最多持续 1 秒**，只提供一小段朝向终点的自动移动，用掉一次机会；时间到立即恢复手动控制。期间仍能攻击，但受到有效命中会立即打断导航，不会恢复或返还次数。失速不会延长导航时限，长按导航键也不会重复触发。
- 导航复用仓库根目录的 `SearchController` / `PathFinder` / `GridMap` / `AgentMove`，使用距离启发式选择方向和深度优先回溯。没有替换成另一套最短路算法，**不保证最短路径**。
- Demo 的导航器在服务端读取完整迷宫求可行路径；玩家和客户端只获得逐步探索的信息。若下一版要求算法也只能看局部地图，需要改为边探索边规划。
- 先抵达绿色信标者获胜。完成后冻结双方状态；被对手击退到终点也算获胜。

## 代码结构与验证

`recovered-src/algorithm` 保留原导航算法；`recovered-src/game/RaceWorld.java` 负责地图、移动、攻击和胜负，`RaceServer` 以 20 Hz 同步状态；`RaceGame` 负责第一人称画面、小地图及共享键盘。恢复源码来自原 JAR 反编译，修复编译问题后可用 Java 21 JDK 完整重建；变量名、注释与原始工程并不完全相同。

```bash
# 仓库根目录：编译、功能检查、1000 个种子的随机地图检查，然后覆盖原 JAR 和 ZIP
bash build-demo.sh

# 发行目录中：无需图形界面的检查
java -cp 'lib/*' RaceChecks
java -cp 'lib/*' RandomMapChecks

# 发行目录中：两个真实窗口的渲染和网络导航检查
# 输出目录必须是本次新建的空目录；保存两张 PNG 和两个 .pass 文件
bash run-demo.sh --visual-check "$(mktemp -d /tmp/gridworld-race-check-XXXXXX)"
```

## 随机地图、公平性与交战机会

- 每局使用新的随机种子，重新生成迷宫、环路、关口位置、出生位置、终点及地图朝向；不是固定地图换皮。地图在公平约束内随机，并非各格独立随机。
- 双方出生点互为镜像，初始朝向也镜像对称；到每个共享关口以及终点的最短路径长度完全相等。双方移动均为每 0.25 秒一格，转向冷却均为 0.20 秒，消除等距赛跑中原先的速度优势。
- 终点在最后一区域随机选择，导航、正常抵达和被炮击推入终点均使用本局终点；中央格不再固定触发胜利。
- 途中有三个无法绕过的共享关口，关口前后有横向交战空间，各区内保留分岔和环路，让双方有多次争夺同一路口的机会。两人速度相同、最短路线等长时，理想起跑可同时抵达首个关口。
- 地图能保证重复交汇的必经位置，不能保证双方在同一时间到达或一定开火；停留、绕路、击退和技术差异会改变到达时刻。没有强制等待对手或强制战斗。
- 保留原有 EMP / 轨道炮的非对称攻击；几何与移动公平不代表武器胜率已达到 50%，竞技平衡仍需实战数据。
- `RandomMapChecks` 检查 1000 个种子：全部道路连通、边界封闭、唯一可达终点、双方等距、三个关口无法绕过、原导航可达、动态终点胜利及击退胜利；另检查 20 次默认新局不重复。

无账号和远程联机，不支持断线重连，无声音资源。双方可以擦身通过，不做玩家实体阻挡；墙壁有碰撞，攻击有遮挡。实际验证平台为 Linux + Mesa 软件渲染。

## 小车模型与展示

侦察兵已改为青色四轮越野车，包含轮毂、轮眉、防滚架、挡风玻璃、尾翼、灯组和车顶 EMP 线圈；重装车为橙色履带装甲车，包含履带块、负重轮、炮塔、炮管、瞄具和发动机格栅。游戏内可见的对手会使用对应模型。

- Windows 双击 `view-cars.bat`；macOS/Linux 执行 `bash view-cars.sh`，打开双车模型展示。
- 展示窗口内按住鼠标左键拖动观察，WASD 移动镜头，Esc 退出。
- 试玩 ZIP 的 `models` 目录附有两份 jMonkeyEngine 原生 `.j3o` 模型和预览图；可通过 `assetManager.loadModel(...)` 导入 jME 项目。
- 可编辑的程序化建模源码是 `recovered-src/game/RaceVehicles.java`。侦察兵 1,312 个三角面，重装车 2,616 个三角面；轮子/履带当前为静态造型。

## macOS 双窗口启动与故障日志

启动器会先等待玩家 1 完成首帧渲染，再启动玩家 2。每个进程使用独立的临时目录，macOS 子进程均带 `-XstartOnFirstThread`，Dock 中显示各自玩家编号。Mac 上两个窗口错位排列，避免第二个窗口超出屏幕或完全盖住第一个；启动脚本优先使用已安装的 Java 21。

如果任一窗口启动失败，终端会保留具体原因及日志路径。日志位于启动目录下 `logs/run-.../player-1.log` 和 `player-2.log`；JVM 崩溃时另有对应的 `player-N-crash.log`。可以将报错日志内容提供给开发者诊断。在 Mac 终端执行 `bash run-demo.sh`，并等待显示两条 `window ready`。本次启动流程及错误处理在 Linux 验证，macOS 特定失败仍需结合实际日志确认。

## 路线策略与评分

玩家 1 使用 W 前进、S 后退、A 左转、D 右转。每次按下转向键转 90°，长按不会连续转圈，松开后再次按下才转下一次；玩家 2 的方向键转向同样按次生效。

初始效率评分为 1000，每实际移动一格扣 10 分，最低 0 分。正常行驶、倒车、自动导航、炮击造成的位移均计步；原地转向、射击和撞墙未移动不扣分。绕路和回头会降低评分，炮击也可增加对手需要弥补的路程。

小地图用角色颜色标出已走过的格子，方便辨认回头路；HUD 实时显示自己的步数和评分。先到终点仍决定胜负，结算另列双方路线效率：对手在比赛中不公开步数，避免暴露其探索进度。未完成玩家可能步数更少、效率分更高，但不能凭停在起点获胜。
